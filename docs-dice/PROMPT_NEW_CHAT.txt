Мы работаем над визуальным оформлением кубиков для моей настольной RPG. В этом чате занимаемся ТОЛЬКО кубиками: текстурами, материалами, рамками, читаемостью цифр и проверкой готовых скинов. Другие части игры не переделываем.

Я прикладываю Dice_Studio_Kit_Collection.zip. Распакуй его и сначала прочитай README.md и PACK_FORMAT.md. Внутри находятся точные шаблоны граней всех шести кубиков, независимая мастерская предпросмотра, код отрисовки и пример подключаемого набора.

Что уже утверждено:
1. Формы: D4, D6, D8, D10, D12, D20.
2. Анимация строго из версии 0.6.92. Файлы arcana/dice-motion.js и arcana/dice-animator.js не изменять. Число оборотов, направления, траекторию, скорости ×1/×2/×4 и результаты бросков не менять. Контрольные суммы есть в animation-lock.json.
3. У каждого героя собственные настройки кубика. Не превращать их в общие настройки игры.
4. Игрок отдельно выбирает цвет рамки, фона и цифр; для каждого есть 15 цветов. Новая текстура должна сохранять эту возможность.
5. Цифры рисует игра отдельно. Не запекать цифры в текстуры.
6. Начинаем с D20. После согласования его вида оформляем остальные пять форм тем же материалом.

Первая задача:
Предложи два визуальных варианта D20 с сатинированной металлической рамкой и слегка потёртой эмалью внутри. Дизайн должен выглядеть как качественный физический кубик красивой настольной игры: выразительный материал, простая рамка, без мелких ненужных украшений. Покажи статичный вид и действующий предпросмотр. Сначала согласуем D20, затем переносим дизайн на весь набор.

Как готовить реальные файлы:
— Для D20 используй templates/d20/d20-guide.svg и маски d20-face-mask.png, d20-rim-mask.png. Их положение и масштаб не менять.
— Каждый слой — PNG или WebP размером ровно 1024×1024 с прозрачностью.
— d20-face.png: фактура фона только внутри соответствующей маски.
— d20-rim.png: фактура рамки только внутри соответствующей маски.
— Фактуры нейтральные, в оттенках серого: движок окрашивает их цветами, выбранными игроком. Белый сохраняет выбранный цвет, серый затемняет, прозрачность открывает лежащую ниже поверхность.
— Не рисуй весь объёмный кубик внутри картинки грани. Не добавляй перспективу, внешние падающие тени, фон сцены, подписи, цифры или направляющие. Объём, движение, цифры и часть освещения создаёт игра.
— Одинаковый рисунок повторяется на всех гранях одного типа. Не нужно рисовать 20 отдельных сторон D20.
— Для других кубиков используй их собственные маски, даже если форма тоже треугольная.

Как проверять:
Запусти serve-lab.py и открой dice-lab.html по HTTP. Файлы рабочего набора расположены в assets/dice/packs/<уникальный-id>/. После замены нажми «Обновить коллекцию». Проверь каждую форму, светлую и тёмную расцветку, скорости ×1/×2/×4, ПК и ширину телефона 320–390 px. Изменение рисунка не должно менять анимацию или выпавшее число. Для просмотра материала можно остановиться на конечном положении кубика.

Финальный результат:
1. Готовые изображения слоёв, а не только концепт или скриншот.
2. ZIP с точной структурой assets/dice/packs/<уникальный-id>/pack.json и файлами слоёв рядом.
3. Корректный pack.json формата rpg-dice-skin-v1 с уникальным постоянным id и редактируемым name (образец и спецификация приложены).
4. Короткая инструкция: распаковать assets в корень игры, добавить отдельную папку, сохранив прежние наборы, обновить страницу, выбрать набор в «Журнал → Кубик → Оформление».
5. Не требовать от меня менять JavaScript, пересобирать игру или повышать версию ради следующего скина. Поддержка внешней папки уже подготовлена отдельно; новый чат должен выдавать только набор оформления.

В архиве установлен ТЕХНИЧЕСКИЙ образец: полосы и простая рамка нужны только для проверки загрузки. Это не согласованный художественный дизайн. Можно использовать генерацию изображений для материалов; финальные слои обязательно подогнать под приложенные маски и проверить в мастерской.

Обязательное требование коллекции:
Каждый НОВЫЙ дизайн выдавай отдельной папкой assets/dice/packs/<id>/, не заменяя studio-sample и другие оформления. Пользователь просто добавляет её в актуальную поддерживающую каталог сборку и повторно открывает «Журнал → Кубик → Оформление». Новый кубик появляется рядом со старыми автоматически. Никаких правок JS, списка вариантов или номера версии ради добавления. После установки пользователь может изменить только name в pack.json; ID и выбор героев должны сохраниться. Для обновления уже созданного дизайна используй его прежний ID. Назови ZIP по ID набора. В финале приложи только ресурсы набора и короткую инструкцию; всю игру заново не поставляй.
