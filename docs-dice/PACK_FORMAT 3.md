# Формат независимого набора кубиков

Каждое оформление находится в отдельной папке `assets/dice/packs/<id>/`. Наборы добавляются одновременно, не заменяя друг друга, и перечисляются в **Журнал → Кубик → Оформление** вместе с прежними встроенными вариантами.

```json
{
  "format": "rpg-dice-skin-v1",
  "id": "steel-enamel",
  "name": "Сталь и эмаль",
  "faces": {
    "20": {"face": "d20-face.png", "rim": "d20-rim.png"}
  }
}
```

`id` — постоянный уникальный ключ: 1–64 строчных латинских букв/цифр/дефисов/подчёркиваний, первый символ буква или цифра. Назовите папку так же. Новый дизайн получает новый ID. При обновлении или переименовании существующего ID менять нельзя: по нему сохраняется выбор героев. `name` — редактируемое отображаемое название, 1–80 символов, русский разрешён. Изменение name не влияет на материал и личные настройки. Повторяющиеся ID считаются ошибкой; такие наборы не включаются в каталог.

В `faces` нужна хотя бы одна форма. Для полного набора добавьте ключи `4`, `6`, `8`, `10`, `12`, `20`. Если формы нет, она использует прежний материал. Если есть только `face`, рамка остаётся программной; если только `rim`, фон остаётся программным. Фактура повторяется на всех гранях соответствующей формы: 20 отдельных картинок D20 не нужны.

## Изображения

- Ровно 1024×1024, PNG или WebP с альфа-каналом; до 8 МБ на файл.
- Латинские имена файлов, цифры, дефис и подчёркивание; без пробелов, подпапок и внешних URL.
- Плоский вид грани, без цифр, перспективы и внешней тени. Фон за маской прозрачен.
- `face` и `rim` — нейтральные серые фактуры, которые умножаются на выбранный цвет. Цветное изображение тоже загрузится, но исказит выбранный игроком цвет; не использовать его для этого проекта.
- Цифры, их цвет и обводку рисует игра. Они всегда поверх оформления.
- Картинка прикреплена к грани; это оформление, а не замена геометрии и не физическая симуляция материала. Рельеф настоящим объёмом не становится.

## Координаты и маски

Файлы `templates/uv-layout.json` и `templates/dN/` получены из реальной геометрии отрисовщика. Наибольший размер контура занимает 896 px; оставшиеся 128 px дают поля по 64 px. Контур центрирован по своему ограничивающему прямоугольнику. Место числа соответствует центру грани и не обязательно совпадает с центром PNG.

- `dN-guide.svg` — только направляющие для художника. НЕ класть его вместо текстуры.
- `dN-face-mask.png` — белая непрозрачная зона фона, остальное прозрачно.
- `dN-rim-mask.png` — белая непрозрачная зона рамки, остальное прозрачно.
- Фон масштабирован на 0,87 относительно центра грани; рамка — кольцо между масштабами 0,88 и 0,97. Эти пропорции уже заложены в маски.
- Нельзя обрезать поля, поворачивать или растягивать одну маску относительно другой. В PNG сохраняется весь квадрат 1024×1024.

Порядок покраски: основная освещённая поверхность → фон набора → рамка набора → блик → цифра. Подробности в `arcana/dice-renderer.js` (drawSurface, drawFace). Локальная проекция текстуры использует существующий Canvas-отрисовщик; перед утверждением обязательно оценить на вращающемся кубике.

## Каталог и обновление

`GET /api/dice-packs` возвращает JSON `{"format":"rpg-dice-catalog-v1","packs":["assets/dice/packs/steel-enamel/pack.json"]}`. Python-сервер автоматически перечисляет непосредственные папки в assets/dice/packs при каждом запросе. Каталог НЕ вписывается вручную в игру. В мастерской такой же обработчик есть в serve-lab.py. На другом сервере нужно обеспечить этот же контракт.

Загрузчик запрашивает каталог и файлы при загрузке страницы и открытии меню; запросы без HTTP-кэша. Для гарантии дождитесь полного копирования папки и снова откройте меню. Подпись материала зависит от содержимого изображений, не от названия набора/версии игры. Перезапуск сервера после добавления или переименования набора не нужен.

Каждый набор проверяется целиком; ошибка одного не блокирует другие. До перезагрузки сохраняется последняя успешно загруженная версия повреждённого набора. Удаление его папки удаляет вариант из доступных, не из личных предпочтений героя: возвращение того же ID восстанавливает оформление. Цвета и скорость всегда хранятся отдельно у каждого героя.
