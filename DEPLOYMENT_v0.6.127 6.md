# Запуск и обновление v0.6.127

Исходная v0.6.126 остаётся отдельным ZIP для отката. Игровые правила, максимум 6 героев в одной партии и независимый слот «Карта» не менялись. Десять клиентов в оценке трафика — несколько комнат, а не десять героев в одной.

## Docker / Timeweb Cloud

В папке проекта есть Dockerfile на Python 3.12. Требуются Docker-совместимый сервис и один экземпляр приложения. Команды для самостоятельного запуска:

```sh
docker build -t rpg:0.6.127 .
docker run --name rpg --restart unless-stopped -p 8080:8080 -e PORT=8080 rpg:0.6.127
```

Сервер слушает `0.0.0.0:$PORT`, по умолчанию 8080. Проверка готовности: `GET /api/health`. На хостинге настройте внешний HTTPS, домен, порт маршрутизации на PORT и health check. Прокси должен сохранять ETag, If-None-Match, Vary и Cache-Control, не кэшировать приватные API-ответы между пользователями. Не заменяйте наши настройки на глобальный долгий кэш HTML/JS. Сжатие на прокси дополнительно не требуется: сервер уже выдаёт gzip; двойное сжатие не нужно.

**Один процесс и одна реплика обязательны для текущей архитектуры.** ROOMS находится в памяти Python. Несколько независимых процессов без общего хранилища не разделяют партии. Комнаты разных игроков в одном процессе независимы. Dockerfile подготовлен, но сборка Docker и размещение непосредственно на Timeweb в этой среде не проверялись: Docker отсутствует, доступа к хостингу нет.

Локальный запуск и Render сохранены: `python3 server.py`, переменная PORT поддерживалась ранее и продолжает работать. Зависимости только стандартной библиотеки Python.

## Сохранения — существенное ограничение

Обновление/перезапуск контейнера очищает оперативную память и серверные комнаты. В этой версии постоянное серверное хранилище **не добавлено**. Существующий механизм восстановления использует снимок и ключ в localStorage браузера; срок актуальности — 3 часа по прежнему правилу. Пока подключённый игрок получает успешные ответы, его отметка активности в локальном снимке поддерживается, в том числе при HTTP 304.

Перед обновлением сохраняйте партии штатной кнопкой «Сохранить» и предупреждайте игроков о перезапуске. Не очищайте данные сайта. Новый домен имеет другой localStorage: браузерные снимки со старого домена автоматически туда не переходят, потребуется файл сохранения. Восстановление из браузера не равно гарантированному серверному резервному копированию.

Просто подключить постоянный диск недостаточно: сервер не пишет ROOMS на диск. Для гарантированного продолжения после перезапусков нужен отдельный этап разработки — запись комнат в SQLite на постоянном диске либо Redis/PostgreSQL с резервным копированием. Это нельзя утверждать уже обеспеченным Dockerfile.

## Обновление через GitHub Desktop

1. Сохраните резервную копию и завершите/сохраните активные партии.
2. Замените файлы проекта содержимым нового ZIP, выполните commit и push обычным способом.
3. Настройка автоматического деплоя из репозитория зависит от выбранного сервиса; в этой задаче аккаунты и репозиторий не изменялись.
4. После запуска проверьте `/api/health`, создание комнаты, подключение второго игрока и «Карты».
5. Игрокам нужно закрыть старые вкладки игры и открыть сайт снова. Сервис-воркер намеренно не подменяет код уже открытой партии.

После собственных изменений JS/CSS выполните `python3 update_asset_versions.py`: HTML получит хэш только изменившихся файлов. Изображения не перекодируются; изменённое содержимое по тому же имени обнаруживается через ETag при следующем запросе. Для HTML, JS, CSS и картинок сервер требует проверку актуальности, но при неизменном содержимом возвращает 304 без файла. Офлайн доступны только уже посещённые и закэшированные ресурсы, а не вся коллекция заранее.
