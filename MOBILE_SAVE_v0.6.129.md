# v0.6.129 — Mobile Optimization, Smart Cache & Save System

## Основа и установка

Основа — последняя выданная в этой задаче v0.6.128. Подключённого GitHub checkout с remote в рабочей папке не было; получать неизвестную более новую ветку из аккаунта не выполнялось. Сборка обновляется через обычную замену файлов, commit и push в GitHub Desktop. Баланс, способности, карточки и правила боя не редактировались.

Запуск: `python3 server.py`, порт через `PORT`. Python использует стандартную библиотеку, включая SQLite. После изменений изображений: `python3 optimize_images.py` (нужен Pillow), затем `python3 asset_manifest.py`. При обычном запуске сервер сам пересоздаёт манифест. Оригиналы не удалены. Серверу нужны права записи HTML/манифестов и файла базы. Пользовательские базы в ZIP не включены.

## Графика

Проанализировано 559 файлов assets. До: 306 460 584 байта; используемые варианты после: 232 204 102 байт, экономия 24,23%. 181 файл получил меньший WebP-вариант; остальные оставлены исходными, поскольку преобразование не уменьшало объём. Сохранены разрешения и пропорции; для каждого преобразованного файла проверено точное совпадение RGBA-пикселей, сохранены ICC/EXIF. Цвет, композиция и прозрачность сохраняются. AVIF и уменьшение разрешения не применялись. Это безопасное сжатие без потерь, а не максимальное возможное уменьшение за счёт детализации.

Варианты лежат в assets/optimized. image-aliases.json и image-source-hashes.json связывают прежний путь карточки с вариантом. Манифест проверяет хэш оригинала: если его заменили без повторного запуска оптимизатора, устаревший вариант перестаёт использоваться. Сервер и SW обслуживают правильный вариант, номер карточки и программные ссылки остаются прежними. image-aliases-active.json генерируется автоматически.

Полная фоновая загрузка графики — около 232,2 МБ плюс небольшие иконки и служебные файлы. Сам ZIP больше, так как сохраняет также все исходники для восстановления.

## Кэш и обновления

Сохранена система v0.6.128: SHA-256, подготовка перед применением, разделение версий вкладок, отсутствие автоматической перезагрузки и статического кэша игровых API. Изменения обнаруживаются и при прежнем номере версии. Идентификатор учитывает также таблицу соответствия изображений.

После появления интерфейса (задержка 8 секунд) запускается необязательный прогрев по 6 изображений, с паузами 5 секунд. Уже сохранённые изображения пропускаются. Параллельные команды вкладок объединяются. Текущие ресурсы экрана загружаются обычным способом и не ждут прогрева. При Save-Data, 2G, скрытой странице или отсутствии сети массовая загрузка приостанавливается; возвращение на страницу или online возобновляет проверку недостающих файлов. Ошибка не вызывает бесконечный цикл; следующий запуск/возврат позволяет повторить.

Лимит нового кэша 320 МиБ / 800 файлов. При оценке заполнения хранилища свыше 80% прогрев останавливается. У браузера запрашивается persist(), но его согласие не гарантировано. На устройстве с недостатком места весь каталог может не поместиться: игра продолжает обычную загрузку по требованию. Сохранения IndexedDB не входят в очистку Cache Storage. Защищённые файлы открытых версий могут временно превышать лимит, как в предыдущей версии.

При запуске с новой версией показывается «Новая версия игры …, идет загрузка», после обязательной проверенной загрузки — «Обновление завершено - перезагрузите игру» и кнопка. Нажатие вызывает штатную синхронизацию/сохранение. Автоматической перезагрузки нет. Фоновая графика не блокирует окно завершения обязательного обновления.

## Мобильное управление

Первопричина воспроизведённого дефекта инвентаря — два вложенных владельца прокрутки. Внешняя рамка теперь фиксирует границы и не прокручивается, внутренний #sheetContent получает доступную высоту и одну вертикальную прокрутку. Свайп по карточкам разрешён, нативное перетаскивание изображений отключено. Размер окна сохранён. Общие представления экипировки и торговли внутри этого контейнера используют тот же механизм.

touch-action ограничивает браузерное масштабирование игровой страницы, сохраняя pan-x/pan-y. Обработчики подавляют только многопальцевый жест и Safari gesture при изменении масштаба; одиночный touchmove не отменяется. Существующий двухпальцевый масштаб карты и её кнопки остаются. Некоторые браузеры/настройки доступности могут разрешать собственное увеличение вопреки ограничениям; физические устройства отдельно не проверялись.

## Два соло-слота

Сохранить/Загрузить открывают ровно два слота IndexedDB rpg-solo-saves / slots. Видны герой, уровень и время. Новая партия отсоединяется от активного слота и ничего автоматически не перезаписывает. После первого ручного выбора слота включается автосохранение только в него. Чужая занятая ячейка требует подтверждения перезаписи; продолжение своей — нет.

Записи транзакционные, payload проверяется SHA-256. Изменения интерфейса собираются с задержкой 600 мс; анимация броска, перемещение и незавершённое исследование/посещение не записываются как завершённый результат. Завершённые устойчивые этапы боя сохраняются; при загрузке используется существующее восстановление боевой фазы. Ручная запись во время многоэтапного действия запрещена. Два слота не заменяют отдельный журнал каждого поддействия; при принудительном закрытии процесса до завершения очередной транзакции сохранится предыдущий подтверждённый снимок.

Экспорт создаёт JSON-файл с состоянием, форматом и контрольной суммой. Импорт проверяет файл и позволяет выбрать слот 1/2 с подтверждением замены. Файл можно перенести на другое устройство и импортировать там. Прежнее сохранение ключа rpgDigitalPrototypeV0648 можно открыть отдельно и затем вручную привязать к слоту; автоматически старые данные не удаляются. В сетевой партии меню локальных слотов недоступно.

В модуле solo-saves.js нет сетевых запросов. Данные соло сохраняются только в браузере. В тесте соло-партии зафиксировано ноль POST. Нет срока истечения; очистка данных сайта/решение браузера может удалить IndexedDB. Экспортируйте важные партии в файл.

## Сетевые сохранения и постоянный диск — необходимая настройка

В сети нет двух слотов. После успешных игровых POST /game/init, /game/state, /game/side, /game/ability, /game/respec сервер транзакционно сохраняет согласованный снимок комнаты в SQLite: героев, состояние, привязки участников, секреты сессий и ревизии. Изображения не сохраняются. Остальные успешные изменения комнаты сохраняют метаданные без продления игрового срока. GET/heartbeat не записывают снимок и не продлевают срок.

Последнее игровое действие получает серверную UTC epoch-отметку lastActionAt. Восстановление из базы допускается строго до lastActionAt + 86400 секунд. После нового игрового POST срок обновляется. Для ещё не начатой комнаты исходная отметка — создание. Активная комната в RAM не удаляется только из-за истечения срока; новое действие снова создаст актуальную запись.

Неактивные комнаты выгружаются из RAM примерно через 5–6 минут и при необходимости загружаются из базы. Очистка проверяется лениво не чаще раза в минуту, без постоянно работающего обхода всех снимков. SQLite хранит запись независимо от памяти процесса. Возврат использует прежнюю кнопку продолжения и playerId/playerSecret из сессии устройства. Чужой секрет даёт 403. Клиентский снимок не может самостоятельно воскресить отсутствующую/просроченную серверную комнату. Если участники ещё не вернулись, баннер показывает «Ожидание подключения игроков»; существующие правила очередности и переподключения сохранены.

**Настройте RPG_SAVE_DB на постоянном диске**, например:

```sh
RPG_SAVE_DB=/var/lib/rpg/rooms.sqlite3 PORT=8080 python3 server.py
```

Для Docker смонтируйте постоянный volume в /data и задайте RPG_SAVE_DB=/data/rooms.sqlite3. Хранятся также служебные WAL/SHM файлы SQLite. Одна реплика/один процесс сервера остаются обязательными: общей многосерверной синхронизации не добавлено.

Без переменной используется data/rooms.sqlite3 рядом с проектом. Такой файл переживает рестарт процесса в той же папке, но **на временном диске Render Free или при замене контейнера гарантии 24 часов нет**. Для гарантии после деплоя нужен постоянный диск, доступный новой сборке. Платные сервисы не создавались; аккаунты хостинга не менялись. Базу и WAL нужно резервировать штатными SQLite-средствами. Секреты сессий находятся в базе; доступ к файлу следует ограничить. Соло-слоты сервер не хранит.

## Что проверено

- 30 серверных регрессионных тестов транспорта/правил/протокола/манифеста.
- 29 тестов набора с повторной загрузкой комнаты и отказом неверному секрету (часть совпадает с предыдущим набором).
- Два теста SQLite с подменой времени: ровно 24 часа, heartbeat не продлевает, новое действие продлевает.
- Два отдельных процесса сервера по очереди открыли один файл SQLite и восстановили одинаковое состояние четырёх игроков на раунде 20.
- Браузер: слот 1, нетронутый слот 2, автосохранение золота, новая партия без замены, reload/load, отсутствие соло POST.
- Экспорт файла, импорт в слот 2 с проверкой суммы, восстановление золота.
- Мобильная эмуляция 390×844: до исправления внутренний контейнер растягивался до 1294px и свайп не прокручивал список. После — 695px видимой высоты, 1294px содержимого, реальный touch-свайп дал scrollTop=452.
- Прогрев кэша: команда загрузила 6 изображений, следующая сохранила прежние и увеличила число ресурсов с 56 до 62.
- Четыре браузерных iframe-клиента и карта: синхронизация, 304 в простое, имитация потери связи, восстановление, reload/resume.
- Обновление: первый/повторный запуск без лишнего окна, повреждённый файл, повтор, частичная загрузка, ручная перезагрузка, отдельные версии вкладок. Модульный SW-тест: квота, офлайн, перезапуск, восстановление кэша, API bypass.

Результаты и скрипты — tests-v129. Браузерные скрипты требуют Playwright и запущенного локального сервера; это инструменты разработки, не зависимость игры. В тесте обновления номер v0.6.130 использовался только в одноразовой копии.

## Честные ограничения и ручная проверка

Физические Android/iPhone, Safari, Яндекс, установленная PWA, реальная перезагрузка телефона, перенос между двумя физическими устройствами и реальный деплой на постоянный диск не проверялись. Использован headless Chromium с эмуляцией экрана и touch. Не выполнена полная ручная партия со всеми предметами/фазами. Не выполнялась полная фоновая загрузка каталога на мобильном соединении: проверена последовательная загрузка партий и повторное использование. Экономия графики измерена по файлам, а не по трафику оператора.

На телефоне проверьте свайпы инвентаря/торговли, выбор предмета после свайпа, pinch страницы и карты, PWA reopen, оба слота и перезапись ДА/НЕТ. Завершите несколько действий, закройте браузер, загрузите слот и сверьте здоровье, предметы, карту и очередь. Экспортируйте файл и импортируйте на втором устройстве.

На тестовом сервере с постоянным volume создайте партию, отключите участников, перезапустите контейнер с тем же volume, вернитесь прежними сессиями. Проверьте отказ чужой сессии. При переносе origin браузер получит новый IndexedDB/Cache Storage: соло переносится файлом; сетевой серверный диск и прежние сессионные ключи нужно сохранить. Локальные и сетевые сохранения не очищаются обновлением клиента.

Диагностика кэша: `await RPGUpdates.diagnostics()`. Ресурсы должны приходить через SW; динамические API — через сервер. Старые документы v0.6.128 по ленивому кэшу/отсутствию постоянных серверных сохранений заменяются этим документом для v0.6.129.
